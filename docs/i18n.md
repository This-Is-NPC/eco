# Translations

The interface ships in English (`en-US`), Brazilian Portuguese (`pt-BR`) and
Japanese (`ja-JP`). Each language is one JSON file in
`overlay/i18n/`; nothing else holds interface text.

## Fix a translation

Edit the value in the language's file and save. A running overlay reloads
the file at once — no restart, no code.

```json
"start.begin": "INICIAR REUNIÃO",
```

## Add a language

Copy `en-US.json` to `<code>.json` (a BCP 47 tag such as `es-ES`), translate
the values, and set:

- `_name` — the language's own name, shown in Settings › Interface;
- `_locale` — the Qt locale used for dates, such as `es_ES`.

The overlay finds the file on its own; it appears in the list.

## Rules

- Keys never change meaning; to reword, edit the value. Keys are grouped by
  screen: `start.*`, `dialog.*`, `session.*`, `kind.*`, `timeline.*`, `composer.*`,
  `history.*`, `detail.*`, `config.*`, `provider.*`, `audio.*`, `error.*`.
- `{name}` is a placeholder; keep every placeholder of the English text.
- Plurals use two keys, `key.one` and `key.other`; languages without plural
  forms repeat the text.
- A key missing from a pack falls back to English; missing from English, the
  key itself shows, so gaps are visible.
- `mise run test` fails when a pack lacks a key or a placeholder, when the
  interface uses a key English lacks, or when a daemon error code has no
  `error.<code>` text.

## Choosing the language

Settings › Interface, stored as `[ui] language` in `config.toml`: a pack's
code, or `auto` to follow the system locale (then its language, then English).

## Errors from the daemon

Error events carry a `code` and `params`; the overlay shows
`error.<code>` filled with the params, and the daemon's English `message` only
when no pack has that code. The terminal always prints the English message.
